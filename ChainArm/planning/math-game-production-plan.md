# 삼각함수(Sin)와 두 점 사이의 거리 공식을 이용한 사슬팔 액션 만들기

제작 기획 초안 · 2026-10-27 · 가제 CHAIN MATH

거리로 사슬이 닿는 곳을 정하고, 각도로 이동 방향을 정한다. 플레이어는 사슬을 걸고 몸을 회전시키며 장애물을 통과한다. 이때 화면에 나타나는 길이와 방향을 수학 공식으로 설명하는 액션형 수학 게임이다.

## 1. 제작 목적과 완성할 결과물

두 점 사이의 거리 공식으로 사슬의 사거리와 길이를 계산하고, 삼각함수로 사슬의 각도에 따른 위치·몸체 회전·대시 방향을 표현한다. 플레이어가 공식을 읽은 뒤 실제 움직임에서 같은 관계를 확인하도록 구성한다.

| 항목 | 기획 내용 |
| --- | --- |
| 형식 | 키보드·마우스로 조작하는 2D 사슬팔 액션 |
| 실행 환경 | 현재 HTML Canvas 프로토타입을 확장한 오프라인 단일 HTML |
| 플레이 목표 | 고정점을 선택하고 스윙·대시·해제를 연결해 도착 지점에 도달 |
| 학습 목표 | 사거리 판단, 사슬 길이 제약, 각도에 따른 좌표와 접선 방향 설명 |
| 대상 | 좌표·피타고라스 정리·삼각비를 배우는 학습자와 수학 구현 시연 관람자라는 가정. 학년과 선수 지식은 미정 |
| 제출물 제안 | 실행 HTML, 제작 기획서, 수학 원리 설명, 검증 결과 |
| 미정 사항 | 제출 형식, 제작 인원, 마감일, 실제 학습 대상, 발표·공개 범위 |

기존 프로토타입의 사슬 연결, 빠른 A/D 반전, 회전 기준 시선, 사슬을 유지하는 대시, 지상 미끄러짐 방지를 이어 쓴다. 이 문서는 추가 제작안을 정리한 것이며 학습 화면과 교육용 코스는 아직 구현하지 않았다.

## 2. 플레이와 수학 학습의 연결

플레이 흐름은 **고정점 찾기 → 거리 판단 → 사슬 연결 → 각도와 시선 조절 → 대시 → 해제·착지 → 다음 고정점**으로 이어진다. 실패하면 가까운 체크포인트에서 다시 시도한다.

| 플레이 행동 | 확인할 수학 관계 | 학습자가 설명할 내용 |
| --- | --- | --- |
| 고정점을 조준한다 | 두 점 사이의 거리와 최대 사거리 비교 | 화면상 가까워 보여도 가로·세로 차이를 함께 계산해야 한다 |
| 사슬에 매달린다 | 고정점에서 플레이어까지의 거리 제한 | 팽팽한 사슬은 일정한 반지름의 원 위에서 움직인다 |
| 스윙한다 | 각도 변화에 따른 Sin·Cos 값 변화 | 같은 길이에서도 각도에 따라 가로·세로 위치가 달라진다 |
| A/D를 바꾼다 | 회전한 몸체의 좌우 방향 | 화면의 좌우와 몸체의 좌우는 다를 수 있다 |
| 사슬을 잡고 대시한다 | 사슬 방향에 수직인 접선 | 현재 위치와 시선으로 대시 시작 방향을 예측한다 |
| W/S로 사슬 길이를 바꾼다 | 반지름과 이동 범위의 관계 | 사슬 길이가 달라지면 닿는 위치와 회전 속도도 달라진다 |

학습 기능은 상황을 관찰하고 예측하는 데 사용한다. 진행 중에는 작은 수치만 표시하고, 자세한 풀이를 볼 때 일시정지해 장면을 살펴보도록 제안한다. 학습 효과는 아직 검증하지 않았다.

## 3. 조작과 사슬팔 규칙

| 입력 | 동작 |
| --- | --- |
| A / D | 지상에서는 즉시 좌우 이동. 사슬 연결 중에는 몸체 기준 좌우 보기와 스윙 조절 |
| 좌클릭 유지 | 사거리 안의 연결 가능한 벽·천장에 사슬 고정 |
| 좌클릭 해제 | 사슬을 해제하고 당시 속도로 비행 |
| Shift / 우클릭 | 사슬을 유지한 채 현재 시선 방향으로 대시 |
| W / S | 사슬 감기·풀기. 기존 벽 등반 동작도 유지 |
| Space | 점프. 사슬 연결 중에는 해제 도약 |
| R / Esc | 체크포인트 복귀 / 일시정지 |
| M — 추가 제작 제안 | 수학 표시 켜기·끄기 |

**회전 기준.** 훅이 걸리는 순간 몸체의 위쪽 축이 고정점을 향한다. 사슬 연결 중에는 매 물리 갱신 후 이 각도를 유지한다. A/D는 회전된 몸체의 좌우를 정하며, 좌우 전환은 몸체의 기준 회전을 바꾸지 않고 시선을 뒤집는다.

**대시 기준.** 몸체의 시선, 분홍 화살표, 대시 시작 방향이 일치한다. 키를 놓으면 마지막 시선을 유지한다. 대시는 사슬을 해제하거나 길이를 바꾸지 않는다. 사슬이 팽팽하면 대시 후 원호를 따라 움직이고, 느슨하면 다시 팽팽해질 때까지 원 안에서 움직인다. 화살표는 시작 속도 방향을 나타낸다.

**조작 반응.** 지상에서 이동 키를 놓으면 수평 속도가 즉시 0이 된다. 스윙 중 반대 키를 누르면 시선은 즉시 바뀌고 접선 속도에는 강한 제동이 적용된다. 반대 입력이 없는 스윙 관성은 유지한다.

**충전과 입력 충돌.** 새 사슬 연결 또는 새 착지로 대시를 충전한다. A와 D를 함께 누르면 마지막 입력을 우선한다. 같은 방향을 유지하면 대시 추진력을 보존하며, 새 반대 입력은 대시 직후에도 방향을 전환한다. 벽·천장에 건 사슬을 핵심 학습 대상으로 삼고, 기존 드론 당기기는 별도 확장 요소로 둔다.

## 4. 사용할 수학 원리

### 4.1 좌표와 기호

화면 좌표는 오른쪽이 +x, 아래쪽이 +y다. 고정점을 H, 플레이어 중심을 P라고 한다. 화면 이동과 확대는 표시만 바꾸며 거리 계산은 게임 안의 좌표로 수행한다.

| 기호 | 뜻 | 단위·기준 |
| --- | --- | --- |
| H = (hx, hy) | 사슬 고정점 | px |
| P = (px, py) | 플레이어 중심 | px |
| rx, ry | 고정점에서 플레이어로 향하는 좌표 차이 | rx = px − hx, ry = py − hy |
| d | 두 점 사이의 실제 거리 | px |
| L | 현재 사슬이 허용하는 최대 길이 | px |
| R | 사슬을 발사할 수 있는 최대 거리 | px |
| θ | 고정점에서 수직 아래쪽을 기준으로 오른쪽을 향해 잰 각도 | 내부 계산 rad, 화면 표시 ° |
| φ | 몸체의 그리기 회전 각도 | φ = −θ |
| s | 몸체 기준 시선 | D는 +1, A는 −1 |
| V | 대시 시작 속력 | px/s |

### 4.2 두 점 사이의 거리

```text
rx = px − hx
ry = py − hy
d = √(rx² + ry²)
```

발사 시에는 조준선에서 실제로 맞은 표면을 H로 삼는다. `d ≤ R`이고 사슬을 걸 수 있는 표면이며 앞을 가로막는 다른 물체가 없을 때 연결한다. 거리는 필요조건이고 표면 판정도 함께 수행한다.

연결 후에는 `d ≤ L`을 유지한다. `d < L`이면 사슬이 느슨하므로 플레이어를 강제로 원 위로 밀어내지 않는다. `d > L`이면 다음 식으로 위치를 최대 길이까지 되돌린다.

```text
nx = rx / d
ny = ry / d
px = hx + L × nx
py = hy + L × ny
```

이때 바깥쪽으로 나가려는 속도 성분도 제거하거나 제한해야 사슬이 계속 늘어나지 않는다. `d`가 거의 0이면 나눗셈을 피하고 직전의 유효한 방향을 사용한다.

현재 프로토타입은 연결감을 위해 처음 사슬 길이를 맞은 거리의 `0.96배`로 줄인다. 그래서 최초 거리와 설정 길이가 잠깐 다를 수 있다. 학습 화면에서는 `실제 거리 d`와 `허용 길이 L`을 따로 표시한다. 기본 수학 예제에서는 이해를 돕기 위해 `d = L`인 팽팽한 사슬을 사용한다.

### 4.3 Sin으로 가로 위치, Cos로 세로 위치 계산

θ는 수직 아래쪽에서 잰 각도다. 팽팽한 사슬의 위치는 다음과 같다.

```text
px = hx + L × sin(θ)
py = hy + L × cos(θ)

sin²(θ) + cos²(θ) = 1
d = √((L × sin(θ))² + (L × cos(θ))²) = L
```

Sin은 사슬 길이 중 가로 방향으로 차지하는 비율이고, Cos는 세로 방향으로 차지하는 비율이다. 각도를 바꿔도 두 점 사이의 거리가 L로 유지되는 이유를 두 식으로 확인한다. Cos는 `cos(θ) = sin(θ + π/2)`로 Sin과 연결된다.

느슨한 사슬의 실제 위치를 표현할 때는 위 식의 L 대신 d를 사용한다. 현재 게임은 속도와 중력으로 위치를 먼저 갱신한 뒤 거리 제약을 적용한다. Sin·Cos는 그 위치의 기하 관계와 방향을 설명하며, 입력과 무관한 일정한 왕복 운동을 지정하지 않는다.

### 4.4 사슬 방향에서 몸체 회전 구하기

```text
θ = atan2(rx, ry)
φ = −θ
몸체의 위쪽 방향 = (−sin(θ), −cos(θ))
```

`atan2`는 두 좌표 차이로 각도를 구하고 어느 사분면에 있는지도 구분한다. 여기서는 수직 아래쪽을 기준으로 잡았기 때문에 인수가 `(rx, ry)` 순서다. 몸체의 위쪽은 언제나 고정점을 향한다. 현재 구현의 `atan2(−rx, ry)`는 φ를 직접 구하는 같은 방향 계산이며, 회전이 이어질 때 각도 경계에서 튀지 않도록 연결한다.

### 4.5 바라보는 방향으로 대시하기

```text
몸체의 오른쪽 단위 방향 t = (cos(θ), −sin(θ))
대시 방향 D = s × t
대시 시작 속도 = V × D

vx = s × V × cos(θ)
vy = −s × V × sin(θ)
```

사슬의 단위 방향 `(sin(θ), cos(θ))`와 t의 내적은 0이다. 따라서 대시 시작 방향은 사슬에 수직이다. 구현에서는 같은 방향을 `(ry/d, −rx/d)`로도 구할 수 있다. 현재 프로토타입은 이 정규화된 좌표 차이를 몸체·입력·대시의 공통 기준으로 사용한다.

| 플레이어 위치 | θ | D를 눌렀을 때 | A를 눌렀을 때 |
| --- | --- | --- | --- |
| 고정점 아래 | 0° | 화면 오른쪽 | 화면 왼쪽 |
| 고정점 오른쪽 | 90° | 화면 위쪽 | 화면 아래쪽 |
| 고정점 위 | 180° | 화면 왼쪽 | 화면 오른쪽 |
| 고정점 왼쪽 | −90° | 화면 아래쪽 | 화면 위쪽 |

같은 D 입력도 몸체가 돌아간 만큼 화면에서의 방향이 달라진다. 사슬을 유지하므로 접선으로 출발한 뒤 거리 제약에 따라 궤적이 휜다. 팽팽한 사슬에서 접선 속력이 같으면 각속도 크기는 `|ω| = V/L`이므로 짧은 사슬일수록 더 빠르게 회전한다.

JavaScript의 삼각함수에는 라디안을 넣는다. 화면에 도 단위로 표시할 때만 `도 = 라디안 × 180/π`로 바꾼다.

### 4.6 수치로 확인하는 예제

고정점이 `H = (100, 100)`, 플레이어가 `P = (340, 280)`인 장면을 사용한다.

```text
rx = 240, ry = 180
d = √(240² + 180²) = 300
L = 300인 팽팽한 사슬
sin(θ) = 240/300 = 0.8
cos(θ) = 180/300 = 0.6
θ ≈ 53.13°
φ ≈ −53.13°
```

설명용 대시 속력을 `V = 1000 px/s`로 두면 D 방향의 속도는 `(600, −800) px/s`다. 화면 오른쪽 위로 출발한다. A를 누르면 `(-600, 800) px/s`가 되어 왼쪽 아래로 출발한다. 속력은 어느 쪽이든 `√(600² + 800²) = 1000`이다. 이 속력은 계산 예제용이며 게임의 기본 대시 수치를 바꾼다는 뜻은 아니다.

## 5. 수학을 보여 주는 화면과 코스

학습 표시를 켜면 고정점 H와 플레이어 P 사이에 직각삼각형을 겹쳐 그린다. 가로선에는 `rx`, 세로선에는 `ry`, 사슬에는 `d / L`, 고정점에는 `θ`를 표시한다. 화면 한쪽에는 현재 좌표·Sin·Cos 값과 대입식을 배치한다. 플레이어 앞에는 몸체의 로컬 오른쪽 방향과 현재 대시 방향을 구분해서 보여 준다.

| 화면 상태 | 플레이어에게 보여 줄 정보 |
| --- | --- |
| 조준 중 | 연결 가능 여부, 실제 교차점까지의 거리, 최대 사거리 |
| 연결 성공 | H·P, d·L, θ, 회전한 몸체와 현재 시선 |
| 사슬이 느슨함 | 실제 거리와 허용 길이를 따로 표시하고 느슨함을 문자로 표시 |
| 대시 준비 | 시선 방향의 화살표, 시작 속도의 가로·세로 성분 |
| 대시 사용 후 | 소모 상태, 재연결·새 착지로 충전한다는 안내 |
| 연결 실패 | 거리 초과·고정 불가 표면·장애물 차단을 구분해서 안내 |
| 학습 일시정지 | 정지한 장면의 삼각형과 계산식을 읽고 다시 진행 |

색상과 함께 선 종류·기호·문자를 사용한다. 수학 표시와 화면 흔들림은 각각 끌 수 있도록 제안한다. 학습 일시정지에서도 값을 읽을 수 있게 한다. 키보드·마우스 외 입력 지원 여부는 미정이다.

교육용 코스는 다음 순서로 재구성한다는 제안이다. 현재 있는 네 구역이 이 학습 순서로 완성되었다는 뜻은 아니다.

| 단계 | 배치와 행동 | 확인할 개념 | 통과 기준 |
| --- | --- | --- | --- |
| 거리 연습 | 서로 다른 거리에 놓인 고정점을 조준하고 연결 | 거리 공식, 최대 사거리 | 닿는 점을 선택하고 도착 지점으로 이동 |
| 각도 연습 | 같은 고정점에서 여러 각도로 스윙하며 표시를 관찰 | Sin·Cos와 좌표 | 각도 변화에 따른 가로·세로 변화 설명 |
| 방향 연습 | 고정점의 위·아래·옆에서 A/D와 대시 사용 | 몸체 기준 좌우, 접선 | 대시 시작 방향을 예측하고 목표 통과 |
| 종합 구간 | 사슬 길이 조절, 여러 고정점, 장애물 통과 | 거리·각도·방향의 결합 | 연결·스윙·대시·해제로 목적지 도달 |

수학 이해는 별도 설명 과제로 확인한다. 새로운 배치의 그림에서 연결 가능 여부와 대시 시작 방향을 먼저 예측하게 하고, 플레이 후 사용한 공식을 설명하게 한다. 조작 숙련과 수학 이해를 구분해 관찰하며 점수 기준과 참여 인원은 실제 학습 대상이 정해진 뒤 정한다.

## 6. 구현 구조와 처리 순서

기존 단일 HTML 안에서 물리 계산과 수학 표시가 같은 상태를 읽도록 만든다. 학습 화면만 별도의 위치·방향을 계산하면 실제 동작과 설명이 달라질 수 있다.

| 데이터 | 역할 | 현재 코드와 연결 |
| --- | --- | --- |
| 플레이어 위치·속도·회전·시선 | 이동과 그리기의 기준 | player |
| 연결 여부·고정점·허용 길이 | 사슬 상태의 기준 | grapple |
| 조준 교차점·표면·거리 | 연결 가능 판정 | aimResult |
| 거리·각도·단위 방향 | 위 상태에서 파생되는 계산값 | getGrappleFrame()을 확장하거나 공유 |
| 입력과 마지막 좌우 입력 | 충돌하는 입력의 우선순위 | getMoveAxis(), syncKeys() |
| 학습 표시 여부·표시용 값 | 수학 설명과 일시정지 화면 | 추가 제작 |

오프라인 게임 내부 상태를 기준으로 처리한다. 데이터베이스나 계정은 사용하지 않는다. 학습 구간을 데이터로 분리할 때에는 `lessonId`를 고유 식별자로, 해당 코스의 `sectorId`를 참조값으로 사용한다는 제안이다. 구간을 바꾸면 이전 학습 표시 상태를 초기화한다.

처리 순서는 입력 수집, 연결·해제·점프·대시 이벤트, 중력과 접선 속도 조절, 위치 이동, 사슬 길이 제약, 충돌·착지 판정, 최종 회전과 시선 확정, 화면 표시다. 연결과 좌우 시선 변경은 입력 이벤트에서도 즉시 반영한다. 리스폰은 진행 중인 사슬과 대시 상태를 초기화하고, 일시정지·창 이탈은 눌린 입력을 지운다.

동시에 발생한 해제와 대시는 먼저 전달된 이벤트 순서로 처리한다. 대시가 먼저면 대시 후 해제되고, 해제가 먼저면 대시 조건이 없어져 실행하지 않는다. 같은 대시 충전으로 여러 번 가속하지 않도록 사용 즉시 소모 처리한다.

| 시작 상태 | 입력·조건 | 결과 상태 | 상태 변화와 확인 방법 |
| --- | --- | --- | --- |
| 지상·공중 | 연결 가능한 표면에 훅 적중 | 사슬 연결 | 고정점 기록, 즉시 회전 정렬, 연결선 표시 |
| 사슬 연결 | A/D 변경 | 사슬 연결 | 즉시 시선 변경, 접선 속도 조절, 화살표 갱신 |
| 사슬 연결 | 충전된 대시 입력 | 사슬 연결 | 충전 소모, 시선 방향 속도 적용, 고정점·길이 유지 |
| 사슬 연결 | 좌클릭 해제·Space | 공중 | 사슬 해제. Space에는 기존 도약 보정 적용 |
| 공중 | 발판에 착지 | 지상 | 사슬이 없으면 몸체를 세우고 불필요한 수평 관성 제거 |
| 모든 플레이 상태 | 위험물 접촉·R | 체크포인트 | 사슬·효과·입력·카메라 초기화 |

거리 0에 가까운 상황, 사거리 경계, 수평 사슬, 고정점 위쪽, 각도의 한 바퀴 경계, 빠른 대시 중 얇은 장애물, 사슬과 지면이 동시에 닿는 상황을 검증한다. 현재 물리 갱신 간격은 `1/240초`다. 이 값이 모든 기기에서 같은 실행 성능을 보장한다는 뜻은 아니다.

## 7. 제작 범위와 순서

| 우선순위 | 제작 항목 | 핵심 플레이에 필요한 이유 |
| --- | --- | --- |
| Must | 현재 사슬팔 조작 보존, 공통 거리·방향 계산, 수학 표시, 기본 학습 구간, 설명서 | 행동과 공식이 일치하는 실행본 완성 |
| Should | 각도별 연습, 사슬 길이 비교, 일시정지 풀이, 흔들림 끄기 | 관찰·예측·비교를 돕는 학습 환경 |
| Could | Sin 그래프에 현재 각도 표시, 플레이 장면 기록, 설명용 자동 시연 | 발표와 반복 관찰 지원 |
| Won't | 온라인 대전, 계정, 결제, 대규모 스토리, 새 전투 시스템 | 이번 사슬팔 수학 주제의 제작 범위 밖 |

| 단계 | 작업 단위·의존성 | 완료 조건 | 담당 역할 |
| --- | --- | --- | --- |
| 기초 정리 | 기존 조작과 함수 확인, 기호·좌표 기준 확정 | 몸체·화살표·대시의 방향과 설명식 일치 | 기획·개발 |
| 수학 표시 | 기초 정리 후 삼각형, d·L·θ, Sin·Cos, 속도 성분 표시 | 실시간 값과 일시정지 값이 실제 게임 상태와 일치 | 개발·화면 구성 |
| 학습 코스 | 수학 표시 후 거리·각도·방향·종합 구간 배치 | 설명한 개념을 해당 구간에서 직접 확인 | 기획·레벨 제작 |
| 학습 확인 | 코스 완성 후 새 배치 예측과 조작 관찰 | 오답 이유와 조작 혼란을 기록하고 수정 항목 결정 | 학습 검토·테스트 |
| 마감 | 검증 후 단일 HTML과 설명 자료 정리 | 외부 파일 없이 실행되고 수식·조작 설명이 일치 | 개발·제작 책임자 |

날짜와 공수는 아직 확정하지 않는다. 제작 인원·가능 시간·측정된 작업 속도가 없기 때문이다. 먼저 수학 표시 한 장면을 완성하는 데 걸린 시간과 수정 작업을 기록한 뒤, 남은 화면·코스·검증 작업을 나누어 일정 범위를 잡는다. 역할별 실제 담당자는 미정이다.

기술 의존성은 기존 HTML과 브라우저다. 수학 표시는 공통 계산 함수에 의존하고, 코스 제작은 표시 검증 뒤에 진행한다. 조작 체계가 바뀌면 학습 설명과 방향 예제를 함께 재검증한다. 외부 서버·외주·유료 라이브러리는 이번 제안에 포함하지 않는다.

## 8. 검증과 완료 기준

| 검증 항목 | 확인 방법 | 완료 기준 |
| --- | --- | --- |
| 거리 계산 | rx = 240, ry = 180 대입 | d = 300 |
| Sin·Cos 위치 | L = 300, sin(θ) = 0.8, cos(θ) = 0.6 대입 | 고정점 기준 위치 차이 (240, 180) |
| 몸체 기준 방향 | 아래·오른쪽·위·왼쪽 고정점 배치 | 방향 표와 시선·화살표·대시 시작 방향 일치 |
| 사슬 유지 | 연결 중 Shift 사용 | 연결 상태·고정점·설정 길이 유지 |
| 길이 제한 | 원 밖 이동과 원 안 이동을 각각 시험 | 팽팽하면 길이 제한, 느슨하면 강제 원 배치 없음 |
| 즉각적인 시선 | A/D 전환 직후 확인 | 속도 반전 전에 시선 변경 |
| 지상 정지 | 이동 키 해제와 착지 확인 | 의도하지 않은 수평 미끄러짐 없음 |
| 경계 상황 | 거리 0 근처, 사거리 끝, 한 바퀴 회전, 고속 충돌 | 잘못된 수치·각도 튐·반복 충전 없음 |
| 학습 화면 | 실제 상태와 표시값 대조 | 같은 좌표 기준과 단위 사용, 표시 반올림과 계산 분리 |
| 학습 이해 | 새 배치 예측 후 공식 설명 | 사거리·좌표·대시 방향의 관계를 설명했는지 기록 |
| 실행본 | 단일 HTML을 복사해 오프라인 실행 | 외부 자원 없이 플레이 가능 |

이전 구현 작업에서는 35개 동작 검사와 대시 방향 72가지 조합을 통과했다. 스윙 반전 56가지 조합에서는 반대 접선 속도에 도달하기까지 최대 83ms가 기록되었다. 이는 기존 코드 검사 결과이며 교육용 화면·코스의 완성이나 학습 효과를 뜻하지 않는다. 이번 기획 작성에서는 게임 코드를 변경하지 않았다.

가장 먼저 확인할 가설은 사슬 각도와 접선 화살표를 함께 보면 새 배치에서도 대시 방향을 예측하는 데 도움이 된다는 것이다. 최소 검증은 한 고정점의 위·아래·옆 배치에서 설명을 본 뒤 다른 배치를 예측하게 하는 방식으로 진행한다. 이해가 어려우면 코스 확장을 보류하고 각도 기준·기호·시선 표시부터 수정한다. 수식과 실제 방향이 다르면 해당 기능의 완료 판정을 보류한다.

## 9. 현재 상태, 수치, 남은 결정

| 항목 | 현재 상태 | 근거·확인할 일 |
| --- | --- | --- |
| 사슬 연결·회전·시선·대시 | 구현됨 | 기존 HTML의 연결·방향·회전 함수 |
| 지상 즉시 정지·스윙 반전 | 구현됨 | 이전 구현 검사 기록 |
| 속도·사슬 길이 등 기존 계기 | 구현됨 | 기존 HUD |
| 좌표 삼각형·Sin·Cos·각도 표시 | 추가 제작 제안 | 수학 표시 단계에서 검증 |
| 교육용 구간과 학습 효과 | 미검증 | 코스 제작과 학습 관찰 필요 |
| 학년·제출 규격·인원·일정 | 미정 | 실제 과제 조건으로 확정 |

현재 기본 사거리 `480 px`, 중력 `1480 px/s²`, 대시 기준값 `1080 px/s`, 사슬 감기·풀기 속도 `280 px/s`는 코드에서 읽은 초기 설정이다. 플레이 수치로 기록하며 학습 난이도에 맞는 최종값으로 승인된 것은 아니다. 실제 대시 속력은 기존 접선 속도와 상한도 반영하므로 매번 1080으로 고정되지 않는다. 수치 조정 담당은 개발 역할이며, 코스 도달 여부와 의도하지 않은 이탈을 보고 조정한다.

기획 검토에서는 조작 규칙과 수학 식의 방향 기준을 맞췄고, 제작 검토에서는 기존 구현과 추가 제안을 구분했다. 일정·학습 성과·공개 권한은 확인된 사실로 간주하지 않는다. 담당 역할과 마감일이 정해지면 단계별 일정만 추가하면 된다.

## 부록. 제작 관리 기록

계획 식별자는 `production-scope-risk`다. 작업량은 수학 표시 화면, 학습 코스, 설명 자료, 검증 장면 단위로 관리한다. 현재는 처리량 자료가 없어 공수 범위와 확정 일정의 신뢰도를 산정하지 않았다. 제작 책임자는 미정이며 사용자가 이 초안의 적용 범위와 최종 결과물을 결정한다.

기존 파일은 산나비를 참고한 팬 프로토타입이다. 학습용 명칭 CHAIN MATH와 직접 그린 도형을 사용하는 안을 제안한다. 새 외부 이미지·음원·인물·생성형 NPC는 제작 범위에 넣지 않았다. 공개·제출에 사용할 기존 자료의 출처와 사용 범위는 최종 자료 목록이 정해질 때 기록한다. 외주가 생기면 결과물·인수 조건·수정 범위·사용 조건을 별도로 정하며 현재는 외주 의존성이 없다.
