## 1 개발 목적과 진행 권한

이 프로젝트에서 UI 아이콘을 몸·무기·환경 장치로 사용하는 2D 플랫포머 프로토타입을 구현한다. 사용자는 기본 이동과 점프가 동작한다고 직접 확인했다. 이 상태를 이어받아 필요한 기능을 작은 단위로 구현하고 검증한다.

사용자는 Antigravity에서 개발을 먼저 진행하려 한다. 설명이나 계획 제시에만 머무르지 말고, 현재 작업 단위의 코드를 직접 구현하고 필요한 프리팹·씬 연결까지 확인한다. 단, 이 문서가 첫 작업부터 전체 구조를 한꺼번에 만드는 지시는 아니다.

전체 설계는 참고 기준이다. 실제 코드와 플레이 결과에 따라 순서·클래스 분리·구현 방법을 조정할 수 있다. 조정할 때는 변경 이유와 영향을 설명한다. 사용자가 중간에 방향을 바꾸면 진행 중인 작업에 반영한다.

프로젝트와 상위 경로의 적용 가능한 AGENTS.md 등 작업 지침을 먼저 확인한다. 이 인계서는 해당 지침이나 사용자의 새 요청보다 우선하지 않는다.

## 2 매번 작업을 안내하는 방식

각 작업을 시작할 때 아래 항목을 짧게 알린다.

1. **프로토타입의 어느 부분인가** — 플레이어 조작, 검 전투, 옷장, C키 설치, 출구 진행처럼 실제 플레이 장면으로 설명한다.
2. **이번에 할 일** — 지금 구현할 작은 작업 하나와 필요한 이유를 설명한다.
3. **작업 위치** — 실제 스크립트, 씬, Hierarchy 또는 Inspector 항목을 짚는다.
4. **완료 확인 기준** — 무엇을 실행하고 어떤 결과를 확인할지 적는다.

그다음 작은 범위로 구현 → 관련 검증 → 결과 보고 순서로 진행한다. 완료 후에는 실제 상태에 맞춰 다음 작업 하나를 선정한다. 사용자가 직접 확인하겠다고 하면 그 결과를 기다린다. 일반적인 구현 선택마다 반복 승인을 요청하지는 않는다.

다음 상황은 구분해 보고한다.

- 코드와 에셋을 읽어서 확인한 내용.
- 실제 컴파일·자동 검사로 확인한 내용.
- Unity Play Mode 또는 빌드에서 확인한 내용.
- 사용자가 실행 확인했다고 전달한 내용.
- 아직 확인하지 못한 내용.

예상 결과를 실제 통과 결과처럼 쓰지 않는다. 새 문제가 생기면 계획 순서를 고집하지 말고, 현재 작업을 막는 문제부터 살펴본다.

### UI 역할

| UI | 몸으로 장착 | 무기로 사용 | 환경 장치 |
| --- | --- | --- | --- |
| 공격 UI | 빠른 이동과 낮은 체력 | 검의 짧고 빠른 근접 공격 | 좌우 방향을 선택하는 수평 발사기 |

### 조작과 핵심 규칙

- A/D 이동, Space 점프, Z 유지 시 무기 주기에 따른 연속 공격.
- 옷장 앞 Enter Hold 완료 시 시간을 멈추고 몸·무기를 교체한다.
- 같은 UI를 몸과 무기에 중복 장착하지 않는다. 반대 슬롯의 UI를 선택하면 두 슬롯을 교환한다.
- 몸 교체 시 현재 체력 비율을 보존한다. 사망 상태를 장비 교체로 부활시키지 않는다.
- C를 누르면 시간과 카메라를 멈추고 유효 포인트 → UI → 필요한 방향을 선택한다.
- 환경 장치는 동시에 1개만 유지하며 새 설치가 확정되면 기존 장치를 제거한다. 취소·실패 시 기존 장치를 유지한다.
- 장치 수명은 14초의 게임 시간이다. 메뉴·히트스톱 정지 중에는 감소하지 않는다.
- 접촉 장치가 설치 순간 플레이어와 겹쳤다면 완전히 빠져나온 뒤 다시 들어와야 발동한다. 발판은 플레이어와 겹치는 배치를 거부한다.
- 발사 후 0.2초 동안 일반 이동·점프 실행을 잠근다. 메뉴 조작은 허용한다.
- 플레이어 피격 무적은 1초를 기준으로 한다. 적에게 같은 무적을 일괄 적용하지 않는다.
- 적을 모두 처치하지 않아도 살아 있는 플레이어가 출구에 도달하면 클리어한다.

몸 능력치, 피해량, 공격 주기, 속력 등 아직 수치가 없는 항목은 Inspector 설정으로 조절 가능하게 둔다. 처음 넣은 튜닝값은 확정 기획값과 구분해 보고한다.

```text

  TemporaryPlatform       물리 발판
  ContactDevice
    LaunchDevice          방향과 적용 축 설정으로 점프대와 발사기 구분

Interactable
  Wardrobe

  MeleeEnemyBrain
  JumpEnemyBrain
  RangedEnemyBrain
```

부모에는 공통 초기화·검사·종료 흐름을 실제로 구현하고, 자식에는 달라지는 행동만 맡긴다. 같은 행동에서 수치·외형만 달라지면 새 자식 클래스보다 에셋·프리팹 설정을 사용한다.

기존 파일은 현재 위치와 .meta를 유지하며 확장한다. 신규 기능은 `C:/Unity/EngineTeamPro/Assets/01.Scripts/Platformer` 아래에 기능별로 추가하는 안을 기준으로 하되, 실제 구현 전에 인접 코드와 이름 충돌을 확인한다. 기존 namespace와 폴더를 한꺼번에 바꾸지 않는다.

UIDataSO는 고정 정의다. 현재 체력·장비 슬롯·남은 쿨타임·활성 장치 같은 실행 상태를 ScriptableObject 에셋에 저장하지 않는다.

## 6 첫 작업을 구체적으로 시작하기

### 작업 1 이동 물리 처리 시점 통일

**프로토타입 부분:** 캐릭터의 공중 이동과 점프대 발사를 위한 기반.

**수정 파일:** [AgentMovement.cs](C:/Unity/EngineTeamPro/Assets/01.Scripts/TAE/AgentMovement.cs)

**시작 전에 읽을 파일:**

- [PlatformPlayer.cs](C:/Unity/EngineTeamPro/Assets/01.Scripts/TAE/PlatformPlayer.cs)
- [플레이어 프리팹](C:/Unity/EngineTeamPro/Assets/03.Prefabs/TAE/Player_Platformer.prefab)
- [TestMove 씬](C:/Unity/EngineTeamPro/Assets/00.Scenes/TAE/TestMove.unity)

**현재 관찰:**

- FixedUpdate는 moveDir.x × moveSpeed를 X 속도에 직접 지정한다.
- Update에서 CalculateAirTime과 ApplyExtraGravity를 호출한다.
- 공중 시간은 Time.deltaTime으로 누적한다.
- Awake는 transform.root에서 Rigidbody2D를 찾는다. 이 의존성 변경은 첫 작업과 분리해 필요성을 판단한다.

**이번 작업 범위:**

- [ ] 현재 사용자 변경과 입력·프리팹 연결을 확인한다.
- [ ] CalculateAirTime과 ApplyExtraGravity 호출을 FixedUpdate로 옮긴다.
- [ ] 공중 시간 누적에 Time.fixedDeltaTime을 사용한다.
- [ ] 비어 있는 Update를 제거한다.
- [ ] 기존 public 메서드와 Inspector 설정을 유지한다.
- [ ] 아직 점프 버퍼·발사·무기·옷장 클래스까지 함께 만들지 않는다.
- [ ] 관련 컴파일과 가능한 Play Mode 검증을 수행하고 결과를 기록한다.

**확인 기준:**

1. A/D 이동과 Space 점프가 기존처럼 동작한다.
2. 접지하지 않은 동안 공중 시간이 증가하고 착지하면 초기화된다.
3. 지연 이후 추가 중력이 적용되며 착지 후 다시 점프할 수 있다.
4. 사용자에게 이미 확인받은 이동·점프를 망가뜨리지 않는다.

이 변경은 기존 추가 중력의 적용 주기를 바꾸므로, 같은 수치라도 점프 궤적이 달라질 수 있다. ‘프레임률 영향이 모두 해결됐다’고 코드 이동만으로 단정하지 않는다. 궤적이 달라지면 이유를 설명하고 플레이 검증을 거쳐 수치를 조정한다.

Unity 실행이 불가능하면 코드 변경과 정적 확인까지만 완료로 보고하고, 실제 점프 궤적은 미검증으로 남긴다. 실행 확인이 필요한 상태를 전체 완료로 표시하지 않는다.

### 시작을 막는 씬 오류가 있는 경우

확인 시점 TestMove에는 다음 삭제 스크립트 참조가 남아 있다. 현재 파일을 다시 읽고, 이미 정리된 대상은 건너뛴다.

| Hierarchy 대상 | 삭제된 스크립트 |
| --- | --- |
| StageManager | StageManager |
| Square (1) | InteractTest |
| Weapon | Weapon |
| Player_Platformer에 추가된 컴포넌트 | Interactor |

해당 참조가 이번 실행을 방해하면 누락 컴포넌트만 정리한다. 사용자에게 이미 제거된 Canvas를 다시 만들도록 요구하거나, 경고를 없애기 위해 플레이어·카메라·발판을 통째로 삭제하지 않는다.

## 7 이후 개발할 순서와 완료 기준

아래는 전체 기능을 놓치지 않기 위한 참고 순서다. 각 묶음 안에서도 작은 작업으로 나누고, 실제 의존성과 실행 결과에 따라 순서를 바꿀 수 있다.

### A 기본 이동과 장치 발사를 연결한다

**플레이 장면:** 발판을 달리고 점프하며 점프대·수평 발사기로 절벽을 넘는다.

작업 후보:

- 작업 1의 물리 처리 정리를 끝낸다.
- 점프 버퍼와 코요테 타임을 각각 0.15초 기준으로 연결한다. 이미 점프를 소비한 공중 상태에서 추가 점프를 허용하지 않도록 확인한다.
- AgentMovement에 발사 속도·적용 축·잠금 시간을 받는 Launch 경로를 만든다.
- Normal / Launch / Knockback / Disabled의 우선순위를 정하고, 일반 이동이 발사 속도를 덮어쓰지 않게 한다.
- 정지된 위치의 시험용 LaunchDevice 하나를 먼저 연결한다. C키 설치 UI 전체는 아직 필요하지 않다.

**완료 기준:** 반대 방향 입력을 해도 발사 후 0.2초 동안 속도가 덮어써지지 않고, 이후 조작으로 복귀한다. 수직 점프대는 기존 X 속도를 유지하는 설정을 지원한다.

### B 검과 적 하나로 전투를 만든다

**플레이 장면:** Z를 눌러 검으로 가까운 적에게 피해를 준다.

주요 대상:

- 기존 PlayerInputReader, PlatformPlayer, HealthModule.
- 신규 CombatController, WeaponBehavior, MeleeWeapon, AttackExecution, HitReceiver.

작업 후보:

- 입력 에셋에 Z 공격과 버튼 유지 상태를 연결하고 생성 클래스를 재생성한다.
- CombatController에서 생존·조작 허용·쿨타임을 검사한다.
- MeleeWeapon은 검과 봉을 판정 모양·범위 설정으로 구분한다. 부채꼴은 원형 후보 검색에 전방 각도 조건을 추가한다.
- 공격 실행마다 별도 AttackExecution을 만들고, Collider 대신 루트의 HitReceiver로 대상을 식별한다.
- 적 1마리에 체력과 피격 수신을 연결한다. 전체 적 AI 3종을 먼저 만들 필요는 없다.
- 플레이어의 무적·피격 연출·넉백을 필요한 순서로 연결한다.

**완료 기준:** 버튼을 누르고 있으면 무기 주기에 따라 공격하며, 허공 공격도 정상적으로 주기를 소비한다. Collider가 여러 개인 적도 한 공격 실행에서 한 번만 처리한다. 죽거나 메뉴 조작 중이면 새 공격을 시작하지 않는다.

### C 시작과 끝이 있는 작은 한 판을 만든다

**플레이 장면:** 이동 → 장치 사용 → 적 공격 → 출구 도달 또는 사망 후 재시작.

주요 대상: StageController, StageExit, ResultView와 플레이어 사망 처리.

- Running / Cleared / Failed 상태를 한 곳에서 관리한다.
- 출구는 살아 있는 플레이어의 도달로 클리어를 요청한다. 적 전멸 조건은 추가하지 않는다.
- 플레이어 사망 시 입력·이동·공격을 차단하고 열린 메뉴와 소유한 실행 상태를 정리한다.
- 재시작으로 장치·투사체·시간 요청·통계가 새 판 상태로 돌아가게 한다.

**완료 기준:** 짧은 테스트 구간을 처음부터 끝까지 수행하고, 사망·재시작도 재현할 수 있다. 이후 콘텐츠는 이 구간에 추가한다.

### D 공통 시간 정지와 메뉴를 연결한다

**플레이 장면:** 옷장이나 설치 메뉴를 열면 화면과 게임이 멈추고 UI는 계속 조작된다.

주요 대상: GameTimeController, PauseHandle, PlayerMenuController, 기존 KTH_HitStop.

- 활성 요청이 하나라도 있으면 정지를 유지한다.
- 메뉴는 자신의 핸들만 해제한다. 다른 메뉴나 히트스톱의 요청까지 지우지 않는다.
- 히트스톱 만료는 실제 시간으로 계산한다. 무기·발사·장치의 시간은 게임 시간을 사용한다.
- 메뉴 동안 카메라 추적·평가를 멈추고 종료 시 복원한다.
- 기존 KTH_HitStop의 외부 호출 계약을 살리면서 시간 제어 요청으로 연결한다.

**완료 기준:** 히트스톱 도중 메뉴를 열어도 히트스톱이 끝났다는 이유로 게임이 먼저 재개되지 않는다. 메뉴를 닫거나 씬을 다시 열 때 정지 요청이 남지 않는다.

히트스톱을 B나 C 단계에서 먼저 사용해야 한다면 이 묶음의 시간 제어 기반을 앞당긴다. 임시로 여러 곳에서 timeScale을 바꾸는 경로를 추가하지 않는다.

### E 옷장에서 몸과 무기를 교체한다

**플레이 장면:** Enter를 길게 눌러 옷장을 열고 몸·무기를 바꾼다.

주요 대상: UIDataSO, EquipmentController, Interactor, Interactable, Wardrobe, WardrobeView와 HealthModule 확장.

- UIDataSO 3종에 고정 정의와 프리팹 참조를 넣는다. 무기의 공격력·주기·판정 설정은 무기 프리팹에 한 번만 저장한다.
- 초기 장비도 같은 장착 경로를 사용한다.
- 두 슬롯의 교환 결과와 새 무기의 준비 상태를 확인한 뒤 장착 상태를 확정한다. 실패하면 기존 장비를 유지한다.
- 체력 비율을 보존하고 무기 교체로 남은 쿨타임을 초기화하지 않는다.
- View는 선택과 닫기를 전달하고 실제 장착·체력·시간을 직접 수정하지 않는다.

**완료 기준:** 몸·무기 개별 변경과 자동 스왑이 동작하고, 반복 교체로 실제 체력이 증가하지 않는다. 메뉴 중 행동이 차단되고 닫은 뒤 정상 복귀한다.

### F C키 환경 장치 설치를 만든다

**플레이 장면:** 시간을 멈추고 화면 안의 포인트를 선택해 발사기·점프대·발판을 놓는다.

주요 대상: EnvironmentManager, EnvironmentDevice, ContactDevice, LaunchDevice, TemporaryPlatform, PlacementPoint, PlacementView.

- 입력 에셋에 Environment 액션과 C 바인딩을 추가한다. Crouch의 기존 C와 충돌하지 않도록 사용 여부를 정리한다.
- 선택한 UI와 방향으로 새 장치를 준비·검증한 뒤 기존 장치를 교체한다.
- 동시에 한 개, 게임 시간 14초 수명을 공통 관리한다.
- 접촉 장치는 초기 겹침과 플레이어의 여러 Collider를 올바르게 추적한다. 정지 상태에서 설치해도 첫 발동 판정이 맞아야 한다.
- 발판은 4타일 폭과 One-way 충돌을 설정하고 플레이어와 겹치는 배치를 거부한다.
- 설치 확정 때만 Installed 이벤트를 보내 통계에 반영한다.

**완료 기준:** 취소·실패 시 기존 장치가 유지되고, 확정 시 하나만 남는다. 메뉴 동안 수명이 줄지 않으며 재진입 제한과 만료·씬 종료 정리가 동작한다.

### G 차크람과 적 행동을 확장한다

**플레이 장면:** 귀환 무기를 던지고, 순찰·점프·원거리 적을 상대한다.

주요 대상: ProjectileWeapon, Projectile, ReturningProjectile, LinearProjectile, EnemyBrain과 적별 행동.

- 차크람은 최대 사거리 이후 소유자에게 귀환하고 Ground 충돌 시 소멸한다.
- 투사체는 무기 소켓 아래가 아닌 월드에 생성한다. 무기를 바꿔도 발사 당시 피해값으로 비행을 이어간다.
- 차크람은 왕복 전체에서 대상당 1회 타격을 기준으로 하며, 동시 투사체의 판정 집합은 독립적으로 둔다.
- 소유자 사망·스테이지 종료 시 남은 투사체를 정리한다.
- 적 행동만 교체하고 이동·무기·피격 수신·체력을 재사용한다.
- 메뉴·정지 중 AI의 상태 전이와 행동 요청도 진행되지 않게 한다. 생존 검사만으로 모든 행동 제약이 충족됐다고 가정하지 않는다.

**완료 기준:** 무기 교체·동시 투사체·소유자 사망·재시작 상황에서 판정과 참조가 섞이지 않는다. 적별 행동이 같은 피해 경로를 사용한다.

### H 전체 맵과 빌드를 마무리한다

**플레이 장면:** 전체 코스를 시작해서 출구와 결과 화면까지 진행한다.

- 초기 전체 맵 참고값은 128 × 18 타일, A~I의 9구간, 옷장 2개, 설치 포인트 7개, 출구 1개다.
- 적 수 참고값은 근접형 7, 점프형 3, 원거리형 2다. 작은 프로토타입의 필수 선행 조건이 아니며 실제 플레이에 맞춰 조정할 수 있다.
- 플레이 시간·처치 수·장치 설치 횟수를 결과 화면에 표시한다.
- 실제 진입 씬을 빌드 구성에 반영하고 빌드에서도 대표 플레이 구간과 재시작을 확인한다.

**완료 기준:** Editor와 빌드에서 같은 시작·진행·종료 흐름을 확인한다. 옷장·설치·피격·사망·재시작을 포함한 대표 경로가 끊기지 않는다.

## 8 구현할 때 특히 확인할 경계

1. **공격 재진입:** 무기 실행 중 피격·사망 이벤트가 발생해 다시 TryAttack이 호출돼도 공격 시작 처리가 중첩되지 않게 한다. 시작 실패와 정상 허공 공격을 구분한다.
2. **피격 대상 식별:** Collider 집합이 아니라 HitReceiver 집합을 쓴다. 무적으로 거부된 유효 접촉도 같은 공격 실행에서 계속 재시도하지 않는다.
3. **공격 실행 종료:** 근접 공격은 모션 종료·해제 시 정리한다. 차크람은 적 타격 후에도 실행을 유지하고 귀환 완료·지형 충돌·소멸 때 종료한다. 일반 탄환의 관통·소멸 규칙은 해당 설정과 구분한다.
4. **체력 이벤트 순서:** 현재 HealthModule은 실제 피해가 발생하면 치명적인 피해에서도 OnHitEvent 다음 OnDead를 발행한다. 설계 그림의 생존 분기를 이유로 이 계약을 무심코 바꾸지 않는다.
5. **사망 후 넉백:** TakeDamage에서 사망 이벤트가 먼저 처리될 수 있다. 이후 넉백 요청이 와도 Disabled/Dead 상태가 다시 이동 상태로 바뀌지 않아야 한다.
6. **체력 비율:** 내부 체력을 float로 바꾸는 것만으로 반복 교체 문제가 자동 해결되지는 않는다. 반올림된 표시값을 다음 교체의 계산 원본으로 재사용하지 않고 기존 정수 API 호환성을 검사한다.
7. **장비 확정과 알림:** 새 무기 준비 실패 시 기존 상태를 유지한다. 관찰자가 중간의 몸·무기 상태를 완성된 장착 상태로 받지 않도록 알림 시점을 정한다.
8. **이전 장치의 제거 알림:** 제거된 장치가 CurrentDevice와 일치할 때만 현재 참조를 비운다. 이전 장치 콜백이 새 장치를 지우지 않게 한다.
9. **다중 접촉:** 플레이어의 Collider 하나만 Exit했다고 초기 발동 제한을 풀지 않는다. 비활성화·제거 시 남은 접촉 참조도 정리한다.
10. **물리 이동과 연출:** 기존 KTH_Knockback의 Transform 트윈과 AgentMovement의 Rigidbody2D 넉백을 같은 대상에 중복 적용하지 않는다. 공용 연출을 쓰는 다른 씬은 보존한다.
11. **정지 요청:** 자신의 핸들만 멱등적으로 해제한다. 전투·결과·메뉴 정지가 겹친 상태에서 한 기능이 전체 정지를 풀지 않는다.
12. **초기화와 직렬화:** MonoBehaviour는 프리팹·컴포넌트 경로로 생성한다. 기존 필드·GUID·Inspector 참조를 보존하고 필수 참조와 잘못된 설정을 진단한다.

## 9 검증과 진행 기록

현재 기능에 맞는 실제 검증을 선택한다. 단순한 설명용 테스트나 구현을 그대로 베낀 테스트로 완료를 대신하지 않는다.

| 검증 대상 | 최소 확인 사례 |
| --- | --- |
| 이동 | 기존 이동·점프, 공중 시간 초기화, 추가 중력, 발사 잠금 후 복귀 |
| 점프 보조 | 착지 직전 버퍼, 발판 이탈 직후 점프, 공중 추가 점프 거부 |
| 전투 | 버튼 유지 주기, 허공 공격, 다중 Collider, 재진입, 사망 후 입력 |
| 체력 | 초기화와 회복의 피격 연출 분리, 치명적 피해, 음수·0 피해, 장비 교체 비율 |
| 장비 | 슬롯 스왑, 실패 시 유지, 쿨타임 유지, 반복 교체와 정수 표시 |
| 설치 | 취소·실패, 동시에 1개, 정지 중 수명, 다중 Collider 재진입, 발판 겹침 거부 |
| 시간 | 메뉴와 히트스톱 중첩, 중복 해제, 비활성화·씬 종료 정리 |
